### 4b. What the original rule outputs — the N loudest slots

Inference keeps the N loudest of the 5 speaker slots. Scored with the true N forced, so this
isolates the cost of *choosing slots by loudness* from the cost of miscounting:

| true N | slots matched to references | **N loudest slots** | cost | loudest N are exactly the talkers | speaker − spare gap, median | gap, 5th pct |
|---|---|---|---|---|---|---|
| 1 | +7.91 | **+7.71** | −0.20 | 96.0 % | +1.90 dB | +0.09 dB |
| 2 | +6.15 | **+3.06** | −3.10 | **13.3 %** | −2.41 dB | −5.92 dB |
| 3 | +5.13 | **+3.41** | −1.73 | 17.7 % | −2.11 dB | −6.11 dB |
| 4 | +4.36 | **+3.66** | −0.71 | 28.3 % | −1.93 dB | −5.58 dB |
| 5 | +3.47 | **+3.47** | 0 | (all 5 kept) | — | — |
| **pooled** | **+4.63** | **+3.65** | −0.98 | | median over N=1..4: **−1.16 dB** | |
| macro, N = 2..5 | +4.78 | **+3.40** | −1.38 | | | |

*gap* = quietest real-talker slot minus loudest spare slot. Negative means a spare slot is
louder than one of the talkers, so loudness keeps the spare and drops the talker: **61.2 % of
N = 1..4 clips.** On the count-correct clips — the true end-to-end case — the loudest-slot
score is the same +3.65 dB pooled.

**+3.65 dB is what the original loudest rule delivers**; +4.63 dB is what perfect slot selection
would deliver, and §4d's rebuild rule — the system's rule since `bc59305` — delivers +4.06 dB. At N = 2 half the improvement is lost (+6.15 → +3.06 dB). Where a
wrong slot is kept, its SI-SDRi against the talker it replaces is typically near 0 dB in the
per-clip records — no better than the unprocessed mixture.

**Why.** Every slot sits 30–35 dB below the mixture (median real-talker slot: −30.2 dB at N = 1,
−33.2 to −34.6 dB at N = 2..5). SI-SDR is scale-invariant, so nothing in the loss rewards a real
talker's slot for being louder than a spare; the silence term only pushes spares below −30 dB,
and once there they are free. Loudness ordering is therefore close to arbitrary once N ≥ 2. The
remedy — a mixture-consistency constraint or a level term — needs retraining (limitation L5).

## 5. The dataloader ablation — the headline experiment

One variable changed: whether `set_epoch()` reached the dataloader workers. With
`persistent_workers=True` it does not, so every epoch re-rendered identical mixtures.

| | frozen (one epoch, repeated) | fresh every epoch | change |
|---|---|---|---|
| distinct training mixtures, counter | 128,000 | 2,560,000 | 20× |
| distinct training mixtures, separator | 12,000 | 360,000 | 30× |
| **counter, dev accuracy** | 85.1 % | **90.6 %** | **+5.5 points** |
| counter, train − val gap | +16.2 pp | **−0.8 pp** | overfitting removed |
| counter, best epoch | 8 of 20 | 20 of 20 | still improving |
| counter, final training accuracy | 99.54 % | 89.8 % | memorisation gone |
| **separator, dev SI-SDRi** | +4.51 dB | +4.59 dB | **+0.08 dB (noise)** |
| separator, final train loss | −6.343 | −6.243 | fits training data *worse* |

**The counter was data-limited; the separator was not.** A 0.488 M classifier can memorise
128,000 examples — it reached 99.5 % training accuracy against 83.3 % validation. A 5.25 M
model regressing waveforms cannot memorise 12,000 mixtures, so repeating them cost it nothing.
The separator is limited by optimiser steps (30,000), not by data.

## 7. Interpretability

**Learned encoder.** 512 filters, 16 samples (2 ms). Peak-frequency quartiles
0 / 1125 / 2359 / 3289 / 4000 Hz; **23 %** peak below 1 kHz, against 47 % for a mel scale and
25 % for a uniform tiling. The basis tiles the band roughly uniformly — it is **not** mel-like.
A peak histogram alone cannot settle whether the encoder is speech-specific; that is left open.

**Mask geometry vs speaker count** (300 test mixtures, 60 per N):

| true N | mask overlap | sparsity | entropy | SI-SDRi |
|---|---|---|---|---|
| 1 | — | 0.822 | — | +8.23 |
| 2 | 0.151 | 0.862 | 0.004 | +6.45 |
| 3 | 0.211 | 0.866 | 0.011 | +4.94 |
| 4 | 0.234 | 0.863 | 0.021 | +4.36 |
| 5 | 0.266 | 0.862 | 0.032 | +3.54 |

The prediction was *overlap rises and sparsity falls*. Overlap rises (+0.114). **Sparsity does
not fall** (+0.040) — half the stated mechanism fails, and the report should say so.

**Does geometry predict quality?** Pooling across N is confounded: N moves both variables, and
across the group means alone their correlation is −0.993.

| | pooled r | **within-N r** | per N |
|---|---|---|---|
| mask overlap | −0.668 | **−0.569** | N2 −0.60, N3 −0.55, N4 −0.49, N5 −0.63 |
| mask sparsity | −0.405 | **+0.082** | N1 −0.73, N2 +0.14, N3 +0.25, N4 +0.32, N5 +0.24 |

**Overlap survives the control**; sparsity reverses sign — a textbook Simpson's paradox. So the
mechanistic claim holds for overlap only: among mixtures with the *same* number of talkers, the
ones whose masks collide are the ones separated badly.

**Two independent models.** Counter confidence vs separator SI-SDRi: pooled r = +0.261, but
**within-N r = +0.033**. The architectural independence is real (the two share no parameters),
but the agreement is **not established**.

**Receptive field (analytic).** L = 16 (stride 8), P = 3, dilations 1…128 per repeat, R = 3:
1,531 encoder frames = 12,256 samples = **1.53 s**, i.e. ±0.77 s around each output sample and
51 % of the 3 s window (0.51 s after the first repeat, 1.02 s after the second). Derivation in
[CHANGES_AND_LIMITATIONS.md §3](CHANGES_AND_LIMITATIONS.md).

### Channel ablation — which learned filters the separator needs (`09_filter_ablation.py`)

600 test clips (120 per N), grouped by job: **denoise only** (N = 1 with noise, 85 clips,
baseline +8.07 dB), **separate only** (N ≥ 2 clean, 101 clips, +4.90 dB), **both** (379 clips,
+4.69 dB). The 512 encoder filters are sorted by peak frequency into 8 bands of 64. Each band is
**hidden from the mask estimator only** (zeroed at the bottleneck input; reconstruction keeps
every channel), and each clip is compared with itself unablated. 95 % CI in brackets.

| band (filter peaks) | denoise only | separate only | both | ÷ random control: denoise | separate |
|---|---|---|---|---|---|
| B1 0–500 Hz | **−4.68** [±0.79] | **−0.77** [±0.15] | −1.02 | **12.1×** [8.7, 16.8] | **12.2×** [7.0, 21.3] |
| B2 531–1125 Hz | −0.90 [±0.16] | −0.32 [±0.07] | −0.30 | 2.3× [1.7, 3.2] | 5.2× [2.9, 9.1] |
| B3 1.1–1.8 kHz | −0.20 | −0.06 | −0.08 | 0.5× | 0.9× |
| B4 1.8–2.3 kHz | −0.07 | −0.02 | −0.01 | 0.2× | 0.3× |
| B5 2.4–2.8 kHz | −0.06 | −0.01 | −0.01 | 0.2× | 0.2× |
| B6 2.8–3.3 kHz | −0.12 | −0.02 | −0.02 | 0.3× | 0.3× |
| B7 3.3–3.6 kHz | −0.06 | −0.01 | −0.01 | 0.1× | 0.2× |
| B8 3.6–4.0 kHz | −0.15 | −0.01 | −0.00 | 0.4× | 0.2× |
| 64 random filters | −0.39 [±0.11] | −0.06 [±0.03] | −0.06 | 1× | 1× |

**What it shows.**
1. **The mask estimator lives on the lowest 128 filters.** Hiding 0–500 Hz costs denoising
   4.7 dB (58 % of its improvement) and separation 0.8 dB (16 %). Every band above ~1.1 kHz
   — 75 % of the filters, since the basis tiles the band uniformly — costs no more than 64
   random filters (0.1–0.9× the control). The encoder spends most of its filters where the
   mask estimator barely looks.
2. **No noise band and no speaker band.** In raw dB every band hurts denoising more, but so do
   random filters (0.39 vs 0.06 dB): denoising-only clips are simply more sensitive. Divided by
   each job's own control, both jobs lean on 0–500 Hz by the same ~12×, and no band's two CIs
   separate. The honest statement is a **shared** reliance on low frequencies — where voiced
   speech carries its fundamental and first harmonics.
3. *Suggestive, not established:* 0.5–1.1 kHz matters relatively more for splitting talkers
   (5.2×) than for removing noise (2.3×); the CIs overlap at 2.9–3.2.

The **full** ablation (band removed from the output too) is context only, because it deletes
signal energy: removing either 0–0.5 or 0.5–1.1 kHz costs denoising ~16 dB, consistent with
speech energy concentrating there. `09_filter_ablation.py`'s first printed verdict compared raw dB and called
all 8 bands "specialised"; that reading was wrong for the reason in point 2 and the script now
divides by the control. The saved `report/runs/ablation_report.json` was re-scored on CPU
(`--rescore`): measurements untouched, all 8 bands now `"clear": false`, the old verdict kept as
`specialisation_raw_db_superseded`. Caveats: one checkpoint, equal-count bands, zero-ablation, synthetic
stationary noise.

## 8. One clip, end to end (notebook 05)

`recipes_test.csv[300]` = `test_n2_00000`, two talkers, 3.0 s.

| | |
|---|---|
| true count | 2 |
| predicted count | **2** — correct |
| counter confidence | **95.56 %** on N=2 (next: 2.91 % on N=3) |
| slot power vs mixture (sorted) | −31.6 *(spare)*, −32.2 *(talker)* \| −34.2 *(spare)*, −34.4 *(talker)*, −35.8 *(spare)* dB |
| what "keep the 2 loudest" keeps | one talker (+3.71 dB SI-SDRi) and one spare (+0.23 dB) |
| what matched slots would give | +3.71 and +3.78 dB |
| what rebuild keeps (the default since `bc59305`) | two spares (+0.23 and −0.23 dB SI-SDRi) |

**The finding — corrected 2026-09-28.** Every slot sits below the −30 dB silence target. The
first write-up read the two loudest slots as the two talkers, ~2 dB above the spares. The
per-clip record from the §4b re-run shows otherwise: the talkers are the 2nd and 4th loudest
slots (matched-slot mean −33.31 dB, spare mean −33.89 dB, gap −2.76 dB; no other assignment of
the five powers fits all three). **The loudest slot is a spare**, so the demo's second track is
not a separated talker and the second talker was dropped. The clip is typical, not unlucky: at
N = 2 the loudest two slots are exactly the talkers in only 13.3 % of test clips (§4b).

Cause as before: SI-SDR is scale-invariant, so the separation loss never asks for an output
level, while the silence term pushes spare slots down; everything drifts to the floor, and
loudness no longer ranks talkers above spares. Raw outputs are ~30 dB below the input, so the
demo writes the separated tracks at one shared boost and prints it.

**Under the rebuild rule this clip gets worse, not better.** Rebuild keeps two spares here, so a
re-run of notebook 05 will write neither talker in the two kept tracks (both are among the
`--all_slots` surplus files). Rebuild wins on average (§4d) and loses on this clip; if the demo
should show a success, pick an N = 2 test clip whose record has `sel_consistent_correct: true`
(about one in four), and say how it was chosen.
